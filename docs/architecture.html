The transport

One USB cable, four serial channels

FaultyCat enumerates as a USB composite device. Each engine owns its own CDC (virtual serial port); the session keeps all four open at once. The target-UART is special — its control verbs ride the scanner channel, but its data flows on a channel of its own.

Why it's built this way

Three load-bearing decisions

Reuse, never re-implement

The wire protocol is firmware-coupled and evolving. faultycat-lab drives faultycmd's existing clients so a firmware change never needs a second edit here.

Depend only on the stable surface

faultycmd's internals moved between 1.x and 3.x. _compat.py imports only from faultycmd.protocols and resolves moved helpers, so an upgrade won't break the package.

Feature-gate, degrade clearly

Leaner firmware builds lack I2C / UART / logic verbs. Those methods raise a plain "upgrade faultycmd" error instead of an opaque AttributeError.
